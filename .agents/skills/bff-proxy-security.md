# Backend-for-Frontend (BFF) Security Architect

## Роль
Архитектор безопасности интерфейсного бэкенда (BFF), ответственный за изоляцию внутренних корпоративных систем (Bitrix24 CRM, ERP, баз данных) от публичного веб-клиента и предотвращение утечек учетных данных.

---

## Главный архитектурный закон: Zero Trust to Client
Браузер клиента считается недоверенной средой выполнения. Любой код, запущенный на клиенте, может быть декомпилирован, модифицирован или перехвачен третьими лицами.

---

## Обязательные стандарты безопасности

### 1. Полный запрет прямых запросов к CRM
- **Изоляция контура**: Клиентский код (React / Vite / JavaScript) **НИКОГДА** не отправляет запросы напрямую к доменам `*.bitrix24.ru`, `*.bitrix24.kz` или вебхукам REST API.
- **Единая точка входа**: Все операции передачи заявок, бронирований и чтения статусов лотов проходят строго через серверный шлюз BFF:
  $$\text{Браузер} \xrightarrow[\text{Public DTO}]{\text{HTTPS}} \text{BFF API (/api/*)} \xrightarrow[\text{Protected Webhook}]{\text{Internal VPC / HTTPS}} \text{Bitrix24 CRM}$$
- **Сохранение существующих маршрутов**: Сохранять существующий Node HTTP middleware и маршрут `/api/leads`; не плодить несовместимые дубликаты (`/api/lead`).
- **Content Security Policy (CSP)**: В продакшене директива `connect-src` фиксируется как `'self'`, блокируя любые попытки скриптов отправить данные на внешние CRM-эндпоинты.

---

### 2. Защита переменных окружения и токенов
- **Запрет клиентских префиксов для секретов**:
  * Категорически запрещено использовать `VITE_`, `NEXT_PUBLIC_`, `REACT_APP_` для любых секретов, токенов вебхуков, ключей интеграции CRM. Все переменные с префиксом `VITE_` компилятор Vite инлайнит в открытом виде в публичные `.js` файлы бандла.
- **Хранение секретов**:
  * `BITRIX_WEBHOOK_URL`, `BITRIX_CLIENT_SECRET` и внутренние ID воронок читаются исключительно на сервере через `process.env`.
  * Файл `.env` никогда не коммитится в Git (контролируется через `.gitignore`). В репозитории присутствует только `.env.example` с безопасными плейсхолдерами.

---

### 3. Изолированный серверный слой интеграции
- **Архитектура адаптера**: Логика взаимодействия с Bitrix24 выносится в изолированный серверный сервис (`server/bitrixAdapter.mjs`):
  * Конфигурируемый таймаут HTTP-клиента (не более 5000 мс), предотвращающий зависание потоков при сбоях CRM.
  * Безопасное логирование: при ошибках запроса к Bitrix24 в логах сервера маскируются токены в URL (заменяются на `***`).
- **Кэширование статусов (Server-side Status Cache)**:
  * Статусы лотов кэшируются на сервере (`server/statusCache.mjs`). Категорически запрещено опрашивать Bitrix24 на каждый hover по карточке квартиры или движение курсора.
- **Локальное сохранение заявок**:
  * Локальная запись в NDJSON-файлы является демонстрационной/аварийной очередью и не должна выдаваться клиенту за подтвержденную регистрацию сделки в CRM.

---

### 4. Маскирование ответов и строгие публичные DTO
- **Запрет проброса сырых ответов**: Сервер ни при каких обстоятельствах не отдает клиенту исходный JSON-ответ Bitrix24 (`result`, `time`, метаданные воронки). Внутренние технические идентификаторы (например, `UF_CRM_1678291`, `STAGE_ID: C3:WON`, `ASSIGNED_BY_ID: 42`) не должны раскрывать топологию CRM.
- **Публичный контракт (Safe Public DTO)**:
  Клиенту возвращается строго ограниченная проекция данных:

```typescript
// Клиентский публичный DTO ответа
export interface SafeLeadResponse {
  success: boolean;
  leadId?: string;      // Публичный непрозрачный идентификатор (UUID)
  message: string;      // Пользовательское сообщение
}

// Пример серверной трансформации
export function transformBitrixResponse(b24Result: any, internalLeadId: string): SafeLeadResponse {
  if (b24Result?.result) {
    return {
      success: true,
      leadId: internalLeadId,
      message: 'Заявка успешно принята в обработку.'
    };
  }
  return {
    success: false,
    message: 'Не удалось зарегистрировать заявку. Попробуйте позже.'
  };
}
```

- **Обработка ошибок без раскрытия стека (No Leakage)**:
  В случае сетевого сбоя или ошибки авторизации в Bitrix24 клиент получает код `502 Bad Gateway` или `500 Internal Error` с обезличенным сообщением, а детальная внутренняя ошибка фиксируется только в серверном журнале с маскированием учетных данных.
