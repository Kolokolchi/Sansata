# Интеграции SAF Avenue

Текущий проект и команды запуска описаны в [README](../README.md); карта экранов — в [SITE-BASELINE](SITE-BASELINE.md). Контракты — в [architecture-contracts](architecture-contracts.md). Никакая общая конфигурация прежнего сайта при запуске не загружается.

## Материалы и каталог

Данные находятся в `src/data/saf-*.json`, локальные медиа — в `src/assets/`. `safMaterials.ts` сопоставляет адреса источников с локальными файлами. Происхождение и ограничения: [SAF-AVENUE-IMPORT](SAF-AVENUE-IMPORT.md). Импорт выполняется существующими скриптами SAF; прямое редактирование dist не является обновлением источника.

Планировки и датированный снимок помещений — разные сущности. Дата снимка 28.09.2026 не подтверждает текущую продажу. Текущее наличие unknown, цена null. Приблизительная геометрия секций/этажей не становится официальной после подключения CRM.

## Панорамы и интерьеры

Тур комплекса: `saf-tour.json`, три JPEG 2:1 и превью в `src/assets/saf-tour/`, компонент `SafComplexTour` → `PanoramaViewer`. Подготовка: `scripts/prepare-saf-panorama-assets.py`. Оригиналы в `3d tour/` сохраняются. yaw/pitch задаются в градусах, 0° по −Z, положительный yaw к +X. Переходы между точками условные.

Карточки квартир и /tour используют `ApartmentScene`, `SafApartmentViewer`, `InteriorEditor` и `src/lib/interior.ts`. Это демонстрационный интерьер, пока не связанный с индивидуальной моделью квартиры. Сохранённые на устройстве дизайны и их ключи не изменены.

Обе песочницы сохраняются отдельно до переноса в квартиры:
- /sandbox/greybox-tour — собственный Three.js HDRI-тур, шесть точек и граф проходов. Формат, координаты, генерация и ограничения подробно описаны в [HDRI-TOUR](HDRI-TOUR.md).
- /sandbox/zems-tour — внешний Matterport iframe и ссылка на оригинал; требует доступа к провайдеру. Доступность и изменения внешнего сервиса не контролируются проектом.

## Серверный API и Bitrix24

Browser → public API → application service → Bitrix adapter → CRM. Vite dev middleware и production Node используют `createApiRouter`.

| Метод и путь | Назначение |
| --- | --- |
| POST /api/leads | Заявка на консультацию, локальная квитанция либо серверное создание лида |
| POST /api/booking | Консультация по квартире; не сделка и не резерв |
| GET /api/apartments/status | Кэш публичных статусов; без настроенной CRM пустая карта |

LeadForm отправляет только на фиксированный /api/leads. Старый единственный вариант пути в единственном числе больше не обслуживается. Ответ содержит публичную квитанцию, а не CRM ID. В status DTO допускаются только ID из существующего снимка SAF, полученные из явных публичных полей CRM; сырое item.id не используется. Это проверка идентичности, а не автоматическое подтверждение актуальности снимка. Публичный интерфейс по-прежнему не объявляет исторические цены и статусы актуальными.

Без CRM заявки сохраняются в .local/leads.ndjson и .local/bookings.ndjson. Это локальные данные, не доставка менеджеру. Ошибка записи не возвращает успех. Размер тела, лимиты и пути задаются в `server/apiConfig.mjs`: 8 КБ, 3 запроса за 10 минут на каждый endpoint заявок, 60 запросов статусов в минуту. Дедупликация и лимиты находятся в памяти одного процесса.

BITRIX_WEBHOOK_URL хранится только в серверном окружении. Разрешён HTTPS к поддержанным доменам Bitrix24; собственный домен требует точного BITRIX_ALLOWED_WEBHOOK_HOSTS. Редиректы отклоняются, запросы ограничены таймаутом. Реальные значения окружения не копировать в frontend, документацию или тесты.

IP берётся из сокета. За reverse proxy требуются одновременно TRUST_PROXY=true и точный TRUSTED_PROXY_IPS; цепочка X-Forwarded-For проверяется справа налево. Для публичной эксплуатации нужны HTTPS, согласованное хранение персональных данных и общее долговечное хранилище лимитов/дедупликации при нескольких процессах.

GitHub Pages — статический режим без Node API: форма показывает ограничения. npm run build:pages использует существующий base /Sansata/. npm start обслуживает dist на 127.0.0.1:4173 после сборки.
