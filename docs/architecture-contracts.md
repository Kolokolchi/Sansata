# Контракты SAF Avenue

## Данные

Сохранять иерархию Building → Section → Floor → Apartment. Не создавать второй каталог или параллельные доменные типы.

- `src/data/saf-plans.json`: опубликованные варианты code, rooms, area, image. Их местоположение по коду разбирает `safSelection.ts`.
- `src/data/saf-stock-snapshot.json`: датированные наблюдения помещений с устойчивым публичным observation ID, номером, секцией, этажом и происхождением. `safInventory.ts` экспортирует существующий тип SafObservedApartment и индексы квартир/этажей/секций.
- Исторические observedStatus/observedPrice не равны актуальным status/price. Сохранять unknown/null, пока нет проверенного текущего источника. Не выводить CRM ID даже при совпадении с номером квартиры.
- `safFloorGeometry.ts` использует прототипные области из существующих JSON. Маппинг приблизительный, отсутствие индивидуального плана показывается явно.
- Общие Panorama, SelectionImage и публичные DTO остаются в `src/types/index.ts`. Типы интерьера — `src/lib/interior.ts`. Не импортировать данные в файл общих типов.

## UI и адреса

Маршруты и компоненты перечислены в [SITE-BASELINE](SITE-BASELINE.md). Использовать siteUrl/sitePath/navigateTo. Сохранять query-параметры, историю, ключи localStorage и состояния карточек. Старые входящие адреса могут показывать короткую подсказку перехода в SAF: это не второй сайт и не загрузчик старого формата.

## API

Существующий Node middleware — единственный периметр. Контракты endpoint и ограничения находятся в [INTEGRATIONS](INTEGRATIONS.md). Публичные ответы не содержат токенов, сырых CRM-сущностей, внутренних ID, телефонных журналов или исключений адаптера. Серверный status allowlist построен по публичным ID текущего SAF-снимка; похожая строка либо внутренний ID недостаточны для публикации.

Бронирование остаётся запросом консультации. Не добавлять сделку или изменение наличия без отдельного подтверждённого серверного workflow. Сохранять origin/content-type/body-limit/anti-spam/idempotency-проверки.

## Туры

Сохранить очистку геометрий, материалов, текстур, render targets, событий и animation loop при размонтировании. Конструктор не пересоздаёт WebGL-контекст при каждом изменении мебели. Песочницы независимы от реестра квартир до явного переноса. Детали HDRI: [HDRI-TOUR](HDRI-TOUR.md).
