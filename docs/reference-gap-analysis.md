**Референсный объект:** ЖК «STAVNI Обводный» (Санкт-Петербург), цифровое решение на базе интерактивного визуализатора

**Целевой проект:** Интерактивный визуализатор ЖК «Shattyq» (Sensata Group), репозиторий `d:\Anti-Gravity\Sansata`

## 1. Обзор архитектуры референсного сайта (Overview of Reference Architecture)

В ходе реверс-инжиниринга публичного веб-сайта ЖК «STAVNI Обводный» по маршруту поэтажного выбора квартир (`/visual/section/66/floor/91/`) была исследована архитектура визуализации премиального девелоперского продукта.

### 1.1. Концепция гибридного рендеринга (Hybrid 2.5D / SVG Architecture)
В индустрии недвижимости существует три основных подхода к визуализации выбора квартир:
1. **Чистый 3D WebGL (Three.js / Babylon / PlayCanvas):** Полностью трехмерная интерактивная сцена здания и каждого этажа.
2. **Растровый Canvas 2D:** Отрисовка подложки и интерактивных зон через контекст `CanvasRenderingContext2D`.
3. **Гибридный векторный SVG поверх высокодетализированного растра (Hybrid SVG / DOM):** Растровый архитектурный чертеж (JPEG/WebP) или высококачественный рендер, поверх которого накладывается масштабируемый инлайн-SVG с замкнутыми полигонами `<polygon>` / `<path>`, а информационные карточки рендерятся в нативном HTML DOM.

**Выбор референса:** Сайт `stavni-obvodny.ru` использует именно **гибридную модель SVG/DOM**.
- На уровне генплана и внешнего осмотра фасадов комплекс может использовать предварительно отрендеренные ракурсы или облегченный WebGL.
- На уровне этажного плана (`/visual/section/:section/floor/:floor/`) выбор квартир реализован строго через **инлайн-векторный SVG**.

### 1.2. Технологические преимущества модели референса:
- **Мгновенный отклик при наведении (Zero-Latency Hover):** Стилизация полигона выполняется напрямую графическим движком браузера через CSS (`fill`, `stroke`, `opacity`), минуя задержки JavaScript-цикла и виртуального DOM.
- **Идеальная четкость (Pixel-Perfect Retina):** Векторные границы квартир масштабируются без потери резкости на любых экранах с высокой плотностью пикселей (HiDPI / Retina).
- **Минимальное потребление памяти и батареи:** В отличие от WebGL, SVG не требует постоянного 60 FPS цикла перерисовки GPU, когда экран статичен.
- **Абсолютная доступность (Accessibility):** Каждому полигону присваиваются семантические атрибуты `role="button"`, `tabindex="0"`, `aria-label`, позволяющие перемещаться по квартирам клавишей Tab и поддерживающие скринридеры.

## 2. Детальное сравнительное сопоставление по архитектурным измерениям

### 2.1. Технология рендеринга (Rendering Technology)
- **Референсный сайт (STAVNI):**
  - Подложка: Архитектурный план этажа высокого разрешения с детализацией мокрых зон, несущих пилонов, вентиляционных шахт и дверных проемов.
  - Слой интерактивности: Инлайн-SVG `<svg viewBox="0 0 W H">` с векторными полигонами квартир.
  - Информационный слой: HTML-тултипы и боковые панели поверх SVG.
- **Текущее состояние Sansata:**
  - В проекте Sansata заложен правильный компонент `SelectionImage.tsx`, принимающий данные подложки и полигонов.
  - **Критический разрыв:** В файле `public/experience.json` массив `selectionMedia` не определен (`undefined`). В результате компонент `Journey.tsx` принудительно переключается на запасной fallback `FloorMap` — схематичную HTML/CSS-сетку 2×2 (`.floor-diagram`) с четырьмя искусственными ячейками (`unit-0` ... `unit-3`) вокруг лифтового ядра (`.floor-core`).
  - Пользователь видит схему с дисклеймером `«Схема вариантов · не поэтажный чертёж»`, тогда как референс демонстрирует полноценный чертеж этажа.

### 2.2. Векторные полигоны и стабильность координатной сетки (Vector Overlays & Scaling)
- **Референсный сайт (STAVNI):**
  - Координаты полигонов жестко привязаны к исходной системе координат чертежа через `viewBox="0 0 width height"`.
  - Задан атрибут `preserveAspectRatio="xMidYMid meet"`, исключающий геометрическое искажение пропорций здания при растяжении экрана.
  - Стили полигонов используют `vector-effect: non-scaling-stroke`, благодаря чему границы квартир сохраняют стабильную толщину в 1,5–2 пикселя независимо от зума и разрешения.
  - Растровое фоновое изображение защищено стилем `pointer-events: none`, предотвращая случайный перехват событий мыши или перетаскивание картинки.
- **Текущее состояние Sansata:**
  - В `SelectionImage.tsx` атрибут `preserveAspectRatio="xMidYMid meet"` не задан явно на `<svg>`.
  - Элемент `<image>` не имеет `preserveAspectRatio="none"` и `pointer-events: none`. Если физические размеры картинки не совпадают с метаданными `data.width`/`data.height`, фоновое изображение центрируется с полями, а векторные полигоны остаются на месте, вызывая визуальный сдвиг стен относительно полигонов (дрейф координат).
  - В `src/styles/journey.css` задано свойство `max-height: 700px`. На мониторах шире 1240px контейнер растягивается до 1380px по ширине, но упирается в высоту, создавая невидимые поля по бокам (pillarbox). При попытке позиционировать внешние DOM-тултипы по ширине контейнера возникает горизонтальный рассинхрон с чертежом.

### 2.3. Переключение этажей и секций (Floor & Section Switching)
- **Референсный сайт (STAVNI):**
  - Вертикальный лифтовой рейл (Floor Rail) с номерами этажей и индикацией наличия свободных квартир на каждом этаже.
  - Кнопки быстрого перехода вверх/вниз (`ChevronUp` / `ChevronDown`).
  - Плавная загрузка данных нового этажа через AJAX/Fetch без мигания экрана и перезагрузки DOM.
- **Текущее состояние Sansata:**
  - Компонент `FloorRail` (`src/features/Journey.tsx:13`) уже реализован: содержит вертикальный стек кнопок этажей, кнопки вверх/вниз и отображает количество опубликованных планировок на этаже.
  - **Ограничение:** Лифтовой рейл жестко зашит на 9 этажей (`Array.from({length:9}, (_,i)=>9-i)`), что корректно для текущей этажности ЖК «Shattyq» (9 этажей), но уступает референсу в универсальности (в референсе этаж `91`).

### 2.4. Состояния наведения и подсветки (Hover & Selection States)
- **Референсный сайт (STAVNI):**
  - Наведение курсора на квартиру изменяет заливку полигона (`fill: rgba(..., 0.45)`).
  - Фоновый эффект диммирования (Dimming): остальные квартиры на этаже слегка приглушаются (`opacity: 0.5`), создавая выразительный визуальный акцент на целевом объекте.
  - Подсветка реализована через CSS `:hover` без вызова React/JS ре-рендеров.
- **Текущее состояние Sansata:**
  - В `Journey.tsx:12` объявлен локальный стейт `const [hover, setHover] = useState<string>()`.
  - При каждом движении мыши в пределы кнопки квартиры и за ее пределы вызываются `setHover(p.id)` и `setHover(undefined)`.
  - Это провоцирует **постоянный холостой ре-рендер всего компонента `FloorMap`** и всех соседних квартир, хотя в файле стилей `journey.css` селектор `.floor-unit:hover` уже меняет границу и тень.

### 2.5. Всплывающие тултипы и информационные карточки (Tooltips & Floating Cards)
- **Референсный сайт (STAVNI):**
  - Интерактивный плавающий HTML-тултип, перемещающийся вслед за курсором или привязанный к центроиду полигона.
  - Отображает богатый набор данных:
    - Номер секции, этажа и квартиры.
    - Комнатность (Студия, 1-комнатная, 2-комнатная и т.д.).
    - Общая площадь (м²).
    - Стоимость (полная цена и цена за м²).
    - Статус продажи («В продаже», «Бронь», «Продано»).
    - Миниатюра (thumbnail) планировки для мгновенной оценки формы комнат.
  - Встроен алгоритм обнаружения коллизий с краями экрана (Edge Collision Detection): если курсор у правого или нижнего края вьюпорта, тултип автоматически смещается влево/вверх.
- **Текущее состояние Sansata:**
  - В режиме `SelectionImage` тултип представлен **исключительно нативным тегом `<title>{label(region.id)}</title>`**.
  - Нативный тег `<title>`:
    - Показывается с системной задержкой браузера в 1,5–2 секунды.
    - Имеет убогий системный вид операционной системы.
    - Не поддерживает верстку, цены, бейджи и изображения планировок.
    - **Полностью не работает на мобильных экранах и планшетах.**

### 2.6. Модальные окна и переходы (Modals & Navigation Transitions)
- **Референсный сайт (STAVNI):**
  - Клик по квартире открывает карточку квартиры во всплывающей шторке (Drawer / Modal) либо выполняет мягкий переход на страницу квартиры `/flat/:id` с сохранением контекста возврата.
  - Все переходы осуществляются строго внутри SPA без перезагрузки документа.
- **Текущее состояние Sansata:**
  - В `FlatExperience.tsx:30,31` обнаружен **критический баг навигации**:
    ```tsx
    onSelect={p => { if (p.id !== id) location.assign(siteUrl(`/flat/${p.id}?view=floor`)); }}
    onSection={s => location.assign(siteUrl(`/visual/section/${s}`))}
    ```
  - Использование `location.assign` вызывает полную жесткую перезагрузку страницы браузером, уничтожение контекста WebGL, сброс оперативной памяти и мигание белым экраном вместо вызова внутренней функции `navigateTo(...)`.

### 2.7. Маршрутизация и глубокие ссылки (Deep Linking & URL State)
- **Референсный сайт (STAVNI):**
  - Маршрут вида `/visual/section/66/floor/91/` является автономным: прямая вставка ссылки в адресную строку сразу открывает этаж 91 секции 66.
  - Поддерживаются произвольные числовые и буквенные идентификаторы сущностей.
- **Текущее состояние Sansata:**
  - В `src/lib/journey.ts:8`:
    ```typescript
    export function journeyRoute(path: string) {
      const match = /^\/visual(?:\/section\/([12])(?:\/floor\/([1-9]))?)?\/?$/.exec(path);
      return match ? { section: Number(match[1]) || 0, floor: Number(match[2]) || 0 } : null;
    }
    ```
  - Регулярное выражение жестко допускает секции только `1` или `2`, а этажи — строго от `1` до `9`.
  - При переходе по ссылке вида `/visual/section/66/floor/91/` роутер Sansata возвращает `null`, и интерфейс падает в заглушку `«Такой секции или этажа нет»`.

### 2.8. Мобильное взаимодействие и Touch UX (Mobile & Touch Interaction)
- **Референсный сайт (STAVNI):**
  - Отсутствие концепции hover на мобильных устройствах решено через сценарий **Tap-to-Preview (Двухшаговый выбор)**:
    - Первый тап по полигону подсвечивает квартиру и открывает компактную выдвижную нижнюю шторку (Bottom Sheet) с краткими характеристиками и кнопкой «Подробнее».
    - Тап мимо полигона сбрасывает выбор и закрывает шторку.
    - Второй тап по кнопке в шторке переводит на просмотр квартиры.
  - Поддерживаются жесты масштабирования (Pinch-to-zoom) и перемещения (Pan) по сложному чертежу этажа.
- **Текущее состояние Sansata:**
  - На тач-экранах первый же тап по элементу этажа сразу вызывает немедленный переход на `/flat/:id`. Пользователь не имеет возможности ознакомиться с параметрами квартиры и случайно переходит по ссылке при попытке скролла страницы.
  - В `journey.css` при ширине экрана < 760px шрифты уменьшаются до 6–7px (`.unit-label small { font-size: 6px; }`), что грубо нарушает требования доступности WCAG 2.1 (минимальный размер шрифта 12px).
  - На чертеже этажа отсутствуют жесты pinch-to-zoom.

## 4. Рекомендуемый архитектурный путь внедрения для Sansata

Для устранения выявленных разрывов и доведения фронтенд-визуализатора Sansata до эталонного отраслевого уровня сформирован следующий пошаговый план модернизации.

### 4.1. Этап 1: Исправление критических дефектов навигации и роутинга
1. **Устранить срыв SPA в `FlatExperience.tsx:30,31`:**
   Заменить `location.assign(siteUrl(...))` на вызов функции клиентской маршрутизации `navigateTo(...)`. Это сохранит непрерывность работы приложения, не будет сбрасывать состояние WebGL и предотвратит белое мигание экрана.
2. **Ослабить ограничения в `src/lib/journey.ts`:**
   Модернизировать функцию `journeyRoute`, разрешив обработку любых числовых и строковых секций и этажей:
   ```typescript
   export function journeyRoute(path: string) {
     const match = /^\/visual(?:\/section\/([a-zA-Z0-9_-]+)(?:\/floor\/([a-zA-Z0-9_-]+))?)?\/?$/.exec(path);
     return match ? {
       section: isNaN(Number(match[1])) ? match[1] : Number(match[1]),
       floor: isNaN(Number(match[2])) ? match[2] : Number(match[2])
     } : null;
   }
   ```

### 4.2. Этап 2: Активация и стабилизация векторного SVG-визуализатора
1. **Стабилизация `SelectionImage.tsx`:**
   - Добавить на корневой тег `<svg>` явный атрибут `preserveAspectRatio="xMidYMid meet"`.
   - На элемент `<image>` добавить `x="0" y="0" width={data.width} height={data.height} preserveAspectRatio="none"` и `style={{ pointerEvents: 'none' }}`.
   - На полигоны `<polygon>` назначить `style={{ pointerEvents: isDisabled ? 'none' : 'visiblePainted' }}` и CSS-класс `vector-effect: non-scaling-stroke`.
2. **Ликвидация холостых ре-рендеров в `FloorMap`:**
   Удалить `const [hover, setHover] = useState<string>()` из компонента `FloorMap`. Визуальное выделение активной квартиры полностью делегировать нативным CSS-правилам:
   ```css
   .floor-unit:hover, .selection-image polygon:hover {
     fill: rgba(48, 34, 130, 0.4);
     stroke: #302282;
   }
   ```

### 4.3. Этап 3: Создание богатого всплывающего HTML-тултипа (Floating Tooltip)
1. Разработать легковесный компонент `ApartmentTooltip`, монтируемый в DOM поверх SVG-контейнера.
2. Позиционировать тултип с помощью CSS `transform: translate3d(x, y, 0)` на основании координат курсора либо центроида полигона, вычисленного по формуле Гаусса (Shoelace formula).
3. Встроить логику предотвращения вылета за границы экрана: если `x + tooltipWidth > window.innerWidth`, инвертировать смещение влево.
4. Выводить в тултипе:
   - Название/номер планировки.
   - Количество комнат и общую площадь (`${flat.area} м²`).
   - Цену: сохранять строго официальные данные («Цена по запросу», если цена `null`).
   - Статус: «Наличие уточняется» для статуса `unknown`.
   - Миниатюру планировки из каталога.

### 4.4. Этап 4: Мобильная адаптация и Touch UX
1. Внедрить двухшаговый выбор для мобильных устройств:
   - Первое касание полигона: фиксирует выбранную квартиру и открывает всплывающую нижнюю шторку (Bottom Sheet) с характеристиками и кнопкой перехода.
   - Повторное касание кнопки перехода: направляет на детальную страницу `/flat/:id`.
   - Касание свободного пространства этажа: закрывает шторку.
2. Привести размеры мобильных шрифтов к стандарту WCAG 2.1 (минимум 12px для вспомогательных надписей).
3. Подключить жесты масштабирования чертежа (Pinch-to-zoom) для детального изучения планировок на экранах смартфонов.

### 4.5. Соблюдение доменных ограничений Sansata (Integrity Mandate)
- **Каталог планировок — не складской реестр:**
